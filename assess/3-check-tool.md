# Step 3: Check the Tool

Before proceeding, confirm that the specific AI tool you intend to use has been approved for use on this project. This is a gate: if the tool is not approved and cannot be brought into compliance, stop.

**If the tool is already on the approved tools list**, this step is a quick confirmation — verify it is approved for the classification level and use type you identified in [Step 1](1-scope.md), then proceed to [Step 4](4-safeguards.md).

**If the tool is not on the approved list**, it must be assessed and approved before you use it. Gather the necessary information using the [tool evaluation template](../templates/tool-evaluation.md), checking it against the [baseline tool criteria](../reference/tool-criteria.md), then submit it to the SRO for approval. 🛑 **Do not begin using an unapproved tool** — do not use it first and seek approval later.

## What "checking the tool" involves

Any AI tool that processes your data is sharing that data with a third party — the AI provider. This holds even for tools that feel like local productivity aids, and it may trigger UK GDPR obligations, contractual requirements, or security policy considerations. Tools may also request broad permissions (calendar, contacts, files, meetings) that expose more data than you explicitly provide.

A tool must meet baseline criteria covering **data residency, retention and training, authentication, audit logging, security certifications, IP terms, risk mitigation, and permissions**. The full criteria and what to check for each are in [Reference: Tool Baseline Criteria](../reference/tool-criteria.md).

**Remember the "stricter wins" principle.** If the client has its own approved-tools list or additional requirements, those take precedence. Check with the client before introducing any tool not already approved for the engagement.
